# Languages (i18n)

The site is available in English (default), French, Italian, Mexican Spanish, Arabic, Urdu, Simplified Chinese and Russian. Arabic and Urdu read right to left.

| Code | Language | `<html lang>` | Direction | URL |
|---|---|---|---|---|
| `en` | English | `en` | ltr | `/`, `/privacy` (no prefix) |
| `fr` | Français | `fr` | ltr | `/fr`, `/fr/privacy` |
| `it` | Italiano | `it` | ltr | `/it` |
| `es` | Español (México) | `es-MX` | ltr | `/es` |
| `ar` | العربية | `ar` | **rtl** | `/ar` |
| `ur` | اردو | `ur` | **rtl** | `/ur` |
| `zh` | 简体中文 | `zh-Hans` | ltr | `/zh` |
| `ru` | Русский | `ru` | ltr | `/ru` |

## How it fits together

- `i18n/config.ts`: the list of languages and their details (direction, native name). Add a language here first.
- `proxy.ts`: serves English at unprefixed URLs and every other language under its prefix. No automatic redirect by browser language.
- `app/[lang]/...`: every page lives under the `lang` segment. `app/[lang]/layout.tsx` sets `<html lang dir>`, fonts and metadata.
- `messages/<code>/<namespace>.ts`: all text. **`messages/en` is the source of truth**; every other language has the same files and the same keys, and TypeScript fails the build if one is missing or has the wrong shape.
- `i18n/server.ts` / `i18n/client.tsx`: how components read the text.

## Reading text

Server components (the default):

```tsx
import { getMessages, getLocale } from '@/i18n/server'

export async function Hero() {
  const m = await getMessages()
  return <h1>{m.hero.title}</h1>
}
```

Client components (`'use client'`):

```tsx
import { useMessages, useLocale } from '@/i18n/client'

export function Thing() {
  const m = useMessages()          // every namespace except legal, guides, meta
  return <button>{m.common.save}</button>
}
```

`legal`, `guides` and `meta` are server-only and never reach the browser. If a client component needs text from a server-only namespace, pass it in as props from a server parent.

Prefer reading text in server components and passing strings down as props to client components. It keeps the browser download small.

## Rules for text

1. **No hard-coded visible text in components.** Every sentence, label, button, `aria-label`, `alt`, `title`, placeholder and error message comes from `messages`. This includes text in `data/*.ts`, charts, tooltips and the AI chat.
2. **Keep keys by meaning, not by position**: `hero.cta.primary`, not `hero.button1`. Lists of items are arrays of objects: `faq.items: { q: string; a: string }[]`.
3. **Placeholders** use `{name}`: `'Save {pct}%'`. Fill with `fmt(text, { pct: 17 })` from `@/i18n/text`. Translators may move placeholders but must keep them.
4. **Links and bold inside a sentence** use tags, so word order can change per language:
   `'Read our <link>privacy policy</link>.'` rendered with `rich(text, { link: (c) => <LocaleLink href="/privacy">{c}</LocaleLink> })` from `@/i18n/text`. Tags do not nest. Translators keep the tag names.
5. **Links to our own pages** use `LocaleLink` (`@/components/shared/locale-link`) or `ButtonLink`, never `next/link` directly, so the visitor stays in their language. Anchors like `'/#pricing'` work.
6. **Numbers, dates, currency**: use `Intl` with the page language (`useLocale()` / `getLocale()`), not hard-coded `'en-US'`. Prices are defined in Pakistani rupees; keep the `Rs` prefix and Western digits (0-9) in every language so amounts read the same everywhere.
7. **Do not translate**: the product name *Plot Ledge*, plan names *Trial, Silver, Gold, Enterprise*, URLs, email addresses, plot and block identifiers such as `A-104`, code, or the names of third-party products (Google Analytics, Vercel, WhatsApp, Anthropic).
8. **Left-to-right and right-to-left**: use logical Tailwind classes, not physical ones. `ms-*`/`me-*` instead of `ml-*`/`mr-*`, `ps-*`/`pe-*` instead of `pl-*`/`pr-*`, `start-*`/`end-*` instead of `left-*`/`right-*`, `text-start`/`text-end`, `rounded-s-*`/`rounded-e-*`, `border-s`/`border-e`. Flip icons that point a direction (arrows, chevrons) with `rtl:-scale-x-100`. Charts and numbers stay left to right (`dir="ltr"` on the chart element).
9. **Words may be much longer or shorter** than English (German-length French, short Chinese). Do not set fixed widths on text; allow wrapping; never rely on single-line buttons.

## Writing and translating

- Plain, direct, specific. Sentence case. Same word for the same thing everywhere (see the glossary).
- Register: polite but modern. French *vous*, Italian neutral phrasing or *Lei*, Spanish *usted*, Russian *вы*, Chinese *您* throughout, Arabic Modern Standard Arabic, Urdu *آپ*.
- Mexican Spanish uses Mexican vocabulary (*lote*, *mensualidad*, *enganche*, *contrato*), not Spain's.
- Arabic and Urdu use Western digits (0-9) in prices and statistics, and the language's own punctuation (، ؛ ؟ ۔ for Urdu).
- Legal pages: translate faithfully, do not simplify the legal effect, keep the structure. **All legal translations need review by a qualified native-speaking lawyer before launch.**

## Adding or changing text

1. Edit `messages/en/<namespace>.ts` first.
2. Make the same change in every other `messages/<code>/<namespace>.ts` (TypeScript lists what is missing: `npx tsc --noEmit`).
3. Run `npm run build`.

## Adding a language

1. Add it to `LOCALES` and `LOCALE_META` in `i18n/config.ts` and to the loaders in `i18n/messages.ts`.
2. Copy `messages/en` to `messages/<code>` and translate.
3. If the script needs a font, add it in `app/[lang]/layout.tsx` and `app/globals.css`.

## Not translated on purpose

- The generated social sharing image (`app/opengraph-image.tsx`) stays English.
- Emails delivered to the Plot Ledge team from the contact form stay English.
- Server logs and developer-facing errors.
